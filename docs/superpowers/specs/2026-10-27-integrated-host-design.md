# Integrated egui + web host, preserving the existing database

User requests one integrated installation and explicit migration of the old egui database. Preserve Windows 11 native/8GB deployment constraints. A single launcher starts Rust API, conventional Caddy static server and egui with exactly the same data directory. Default remains original `%LOCALAPPDATA%/UrdWMS` (URDWMS_DATA override); no separate empty web data silo. Both local egui and API use existing transaction-protected shared service layer. Remote clients use browsers.

Before upgrading an existing unversioned egui schema: verify DB integrity, make a consistent SQLite backup (including committed WAL data), preserve uploads, migrate transactionally and version the schema. Unsupported future versions or failures must abort without silently reinitializing or resetting records/accounts/settings. Existing user identities/password hashes are reused, no demo seeding unless explicitly requested. Test migration on representative historical schema and WAL DB, idempotency, failure handling and visibility between independent egui/API connections.

Desktop detects external database commits with PRAGMA data_version and refreshes cached data/session status without replacing unsaved form input. Browser refresh/reload reads the same shared data. The launcher keeps server running if egui is closed; Ctrl+C stops owned processes. Package both Windows executables, static web assets, Caddy, required DLLs, licenses and a one-click launcher. Rebuild Windows x64 and verify PE imports; report native Windows runtime limitation.
